# Security

OpenVocally hears your voice, reads your keyboard shortcuts and writes to your clipboard. This page explains how to report a vulnerability and what the app does with each of those.

## Report a vulnerability

Report it privately through GitHub. On the [Security tab](https://github.com/MateuszRomek/openvocally/security) of the repository, click **Report a vulnerability**. Do not open a public issue, pull request or discussion for a security problem.

Include the OpenVocally version, your macOS version, the steps to reproduce, and what an attacker could do. Leave out real transcripts and recordings.

You get a reply in the report within 7 days. After the fix ships in a release, the advisory is published with credit to you, unless you ask to stay anonymous.

## Supported versions

Only the latest release gets security fixes. Release builds update themselves, so a fix reaches users through the normal update. A build from source is supported when it is built from the latest commit on `main`.

## How the app handles your data

### Microphone

The app records only during a dictation: from the shortcut press until the release, or between two presses in toggle mode. Release builds hold one entitlement, `com.apple.security.device.audio-input` (`App/Resources/OpenVocally.entitlements`). Builds from source signed with the local identity (`scripts/install.sh`, `scripts/run-debug.sh`) also hold `com.apple.security.cs.disable-library-validation`. A self-signed identity has no Team ID, so without it macOS would refuse to load `Sparkle.framework`. Developer ID release builds never hold it, and `scripts/release.sh` checks that.

While the app transcribes, it keeps the audio in a file under its data folder. It deletes the file when the transcript arrives. If a dictation fails, the app keeps that audio for 7 days and then deletes it (`OpenVocallyKit/Sources/Storage/RecordingArchive.swift`).

### Accessibility

The app needs Accessibility permission for three things:

- A keyboard event tap that detects your shortcuts. It matches each key event against your shortcuts and stores no keystrokes.
- A synthetic Command-V that pastes the transcript.
- A read of the focused element's role in the frontmost app, to check that a text field can take the paste.

The code is in the `Hotkeys` and `Paste` modules.

### Clipboard

To paste, the app saves the current clipboard, writes the transcript, posts Command-V, and restores the saved clipboard less than a second later (`OpenVocallyKit/Sources/Paste`).

- The transcript is written for this Mac only, so it does not reach other devices through Universal Clipboard.
- The transcript carries the `org.nspasteboard.TransientType` and `org.nspasteboard.AutoGeneratedType` markers, so clipboard managers that follow nspasteboard.org skip it.
- If no text field has focus, the transcript stays on the clipboard for up to 10 seconds, so you can paste it yourself. The restore runs after that.
- If you copy something before the restore runs, your copy wins and the app restores nothing.
- If the saved clipboard was marked as concealed, such as a password from a password manager, the app leaves the clipboard empty instead of writing the secret back.

### Network

Dictation runs on your Mac. The app connects to the network for two things:

- Speech model downloads. When you pick a model, the app downloads its files from Hugging Face (`huggingface.co`) at a pinned revision, and checks each file's size and SHA-256 against the manifest compiled into the app (`OpenVocallyKit/Sources/Models`). It sends no audio or text.
- Update checks, in release builds only. Sparkle reads the update feed from this GitHub repository and downloads updates from GitHub Releases. Sparkle's system profile is turned off, so a check sends no hardware details. You can turn automatic checks and automatic installs off in **Settings > Updates**. Builds from source have no updater and make no update checks.

The app also watches whether the Mac is online during setup, so it can retry a model download. That reads network interface state and sends nothing.

### Updates and code signing

Release builds are signed with a Developer ID certificate, notarized by Apple and run with the hardened runtime. Each update is signed with an EdDSA key, and Sparkle installs an update only when its signature matches the public key built into the app. `scripts/release/update-e2e.sh` tests that an update signed with a different key is refused.

### Data on your Mac

The app keeps its data under `~/Library/Application Support/<bundle ID>`:

- `openvocally.sqlite` holds transcripts, the target app of each dictation, statistics and shortcuts.
- `recordings/` holds the audio described under Microphone.
- `local-models/` holds the downloaded speech models.

Transcripts are kept until you delete them. **Settings > History** deletes them after 7, 30 or 90 days, or all at once. The app has no account and no analytics.

The app logs through the macOS unified log. Transcripts, audio and clipboard contents are logged only as private values, which macOS redacts. The diagnostics file from **Settings > Support** leaves out transcripts, audio and device names.

The app is not sandboxed: its entitlements files have no `com.apple.security.app-sandbox` key. Posting Command-V into another app needs Accessibility access that the App Sandbox does not grant.
